# 보안 경계와 실패 처리

## 권한 범위

잠금 해제는 개별 명령 승인이 아니라 **모델에 열리는 넓은 권한**입니다. sudo 정책이 허용하는 절대 실행 파일과 인수를 모델이 선택할 수 있으며, 신뢰하지 않는 프로젝트 텍스트도 모델 선택에 영향을 줄 수 있습니다. `sudo_exec`는 쉘을 사용하지 않지만 실행 파일 또는 그 자식이 쉘을 띄우는 것은 막지 않습니다. 짧은 시간을 선택하고 요청을 검토하며, 사용을 마치면 `/sudo lock`을 실행하세요.

`SUDO_ASKPASS` 환경 변수가 있으면 별도 옵션 없이 OS askpass를 선택하며, 없으면 터미널 인증을 사용합니다. 설정된 값이 유효하지 않거나 인증이 실패하면 터미널 방식으로 조용히 대체하지 않습니다. askpass 모드는 기존 환경 변수 `SUDO_ASKPASS`의 절대 경로만 사용합니다. 실경로의 도우미는 root 소유의 실행 가능한 일반 파일이고 그룹/전체 쓰기가 금지되어야 하며, 실경로의 모든 상위 디렉터리도 root 소유·그룹/전체 쓰기 금지여야 합니다. 심볼릭 링크는 정규화된 대상을 검증합니다. 사용자 쓰기 가능한 Homebrew/홈 디렉터리 스크립트는 제외됩니다. 확인 대화상자에 모드와 도우미 경로가 표시되고 인증 직전에 재검증하며 선택한 실경로가 바뀌면 거부합니다. 검사와 sudo의 실제 도우미 실행 사이의 파일 교체 경합까지 막지는 못합니다. 확인 화면에서 숫자 `2`는 경고가 모두 보이는 경우에만 추가 확인 없이 바로 승인하며, `1`은 즉시 거절합니다. Enter만 누르면 기본값 NO이고 Pi 선택 키로 이동·확정할 수도 있습니다. sudo 인증 자식에게만 도우미 환경 변수를 전달하고 표준 입출력은 무시합니다. GUI 환경이 없으면 인증이 실패할 수 있습니다. 이 정책은 같은 UID 프로세스를 sandbox하지 않으며 악의적인 root 또는 root 소유 도우미의 안전성을 보장하지 않습니다.

터미널 모드에서 일반 화면은 TUI를 중지하며 기존 UI 아래로 커서를 옮긴 후 sudo 자체 인증 프롬프트만 표시합니다. 인증 출력으로 기존 렌더 위치가 무효화되므로 재개 시 현재 커서 위치부터 UI를 한 번 다시 그리되 화면·스크롤백 전체를 지우지 않습니다. fullscreen은 화면 보존 옵션으로 중지해 대화 기록을 일반 화면에 출력하지 않으며, 보조 화면 종료·재진입 전환은 일어납니다. 터미널 인계 중 Ctrl+C(SIGINT)는 확장의 임시 핸들러가 받아 인증·시험을 취소하고 논리적 접근을 즉시 철회합니다. 직접 자식 종료와 sudo 캐시 무효화는 별도로 기다리며, 그 실패를 숨기지 않습니다. 비밀번호는 이 확장의 Pi 입력 위젯, 모델 도구 인수, 캡처 파이프나 출력에 저장·전달하지 않고 `sudo -v`의 상속된 실제 터미널에서 처리합니다. 터미널 기록, sudo/PAM 정책은 별도 영역입니다. **도구 명령의 stdout·stderr에는 비밀 정보가 포함될 수 있으며 Pi의 도구 결과로 전달됩니다.** 화면용 출력은 제한된 도착 순서의 끝부분만 보관하고 펼쳐도 버린 내용을 복원할 수 없습니다. 성공 모델 텍스트는 두 스트림의 접두부, 실행 실패 오류 텍스트는 제한된 출력 끝부분을 포함할 수 있습니다. 민감한 명령을 실행하지 마세요.

## 시스템 sudo AUTO 선택

고정 `/usr/bin/sudo`가 우선입니다. 시스템이 이 경로를 sudo-rs 공급자로 제공해도 그대로 사용하며 구현 언어를 추정하여 바꾸지 않습니다. 이 경로에 항목이 **없을 때만** 고정 `/usr/bin/sudo-rs`(예: Arch의 별도 바이너리)를 선택합니다. PATH·쉘 alias·사용자 설정 경로를 탐색하지 않습니다. 존재하는 기본 경로가 위험하거나 접근 불가·깨진 심볼릭 링크이면 다른 백엔드로 대체하지 않습니다.

선택 항목과 정규 대상은 root 소유여야 합니다. 정규 대상은 일반 실행 파일이며 그룹/전체 쓰기가 금지되어야 하고, 고정 경로의 상위 디렉터리와 정규 대상의 모든 상위 디렉터리도 root 소유·그룹/전체 쓰기 금지여야 합니다. 신뢰할 수 있는 심볼릭 링크는 허용하지만 정규 대상으로 실행합니다. 확장 로드에서 실제 호스트 파일 검사를 수행하지 않고 인증/정리 시 지연 선택합니다.

새 명시적 `/sudo unlock`에서 백엔드를 선택하며 인증 `-v`/`-A -v`, 비대화형 시험 `-n -- /usr/bin/true`, 실제 실행과 `-k` 정리에 같은 정규 경로를 사용합니다. 각 자식 호출 전후에 선택 경로·정규 경로·파일 신원(dev/inode, 소유자·모드·크기·수정/변경 시간)을 비교합니다. `/sudo reauth`는 기존 백엔드를 그대로 요구하며 바꿔서 인증하지 않습니다. 기본 경로가 새로 생기거나 사라짐, 링크 재지정, 바이너리 교체 또는 신뢰 검사 실패가 감지되면 논리적 접근을 먼저 철회하고 새 `/sudo unlock`을 요구합니다. **자동 백엔드 재시도·인증 재시도·명령 재실행은 없습니다.** 변경된 바이너리로 `-k`를 대신 실행하지 않으므로 기존 OS 캐시가 남을 수 있습니다. 재인증이 자식 호출 전에 거절되는 경우도 캐시 잔류 경고를 알리고 `⚠️ sudo` 상태를 유지합니다. 적절한 관리자 점검이 필요합니다.

이 검사는 파일 내용 서명·해시 검증이나 열린 실행 파일 핸들 기반 실행이 아닙니다. 검사와 실제 spawn 사이의 TOCTOU 경합을 없애지 못하며 root의 악의적 교체나 메타데이터를 보존한 변경까지 모두 탐지한다고 보장하지 않습니다. 변경 감지는 호출/재인증 시 수행하며 별도 파일 감시로 즉시 철회하지 않습니다. 같은 UID·TTY 캐시 공유와 후손 종료 한계도 그대로입니다.

### sudo-rs와 자동 askpass

`SUDO_ASKPASS`가 있으면 두 백엔드 모두 별도 flag 없이 검증된 도우미로 `-A -v`를 사용합니다. 공식 [sudo-rs 0.2.11 릴리스](https://github.com/trifectatechfoundation/sudo-rs/releases/tag/v0.2.11)에서 askpass 지원이 추가되었고, 대상 Arch 패키지 버전 0.2.15는 그 이후 버전입니다([Arch 패키지 정보](https://archlinux.org/packages/?name=sudo-rs)). 패키지 버전/배포 상태는 바뀔 수 있으며 이 작업에서 실제 설치본을 조회하거나 OS 통합을 시험하지 않았습니다.

런타임은 버전 문자열로 기능을 추정하거나 `--version`/`--help`를 추가 호출하지 않습니다. 선택한 백엔드의 실제 `-A -v` 성공과 별도 비대화형 시험이 모두 필요합니다. 구형 미지원 버전의 옵션 거부나 인증 실패는 askpass 지원 필요·무대체 오류로 끝나고 잠긴 채로 남습니다. 터미널 인증이나 classic sudo로 조용히 바꾸지 않으며 인증 stderr로 지원 여부를 판별하지도 않습니다. Pi가 비밀번호를 캡처하거나 stdin으로 전달하는 경로는 없습니다. 버전이 새롭다는 사실만으로 GUI 환경·도우미·sudo 정책과의 통합 성공을 보장하지 않습니다.

## 확장 접근과 OS 캐시는 별개

잠금 해제는 순서대로 별도 `sudo -k`(기존 timestamp 무효화), 대화형 `sudo -v`, 비대화형 `sudo -n -- /usr/bin/true` 시험을 실행합니다. `-k`와 `-v`를 하나로 합치지 않습니다. 시험 명령이 sudo 정책에서 허용되지 않으면 잠금 해제는 실패합니다. 상태 표시줄의 `⚡ sudo M:SS`와 `/sudo status`는 확장 허가의 남은 상한만 나타내며 OS 인증 캐시 잔여 시간을 조회하지 않습니다. 실제 명령은 `sudo -n`을 사용하므로 정책이 거부하거나 sudo timestamp가 먼저 만료되면 프롬프트 없이 실패합니다. 성공한 실제 sudo 실행이 OS timestamp를 갱신할 수 있지만 확장 기한은 갱신하지 않습니다. `/sudo reauth`는 살아 있는 허가에서만 시작하고 사용자 확인 전에 확장 접근을 철회합니다. 확인 거부·취소·실패·도중 만료 시 잠긴 채로 남고 OS 캐시 무효화를 시도합니다. 재인증에 성공해도 확인·인증 시간을 포함한 원래의 단조·벽시계 기한을 유지하며 명령을 자동 재시도하지 않습니다.

기한은 단조 시간과 벽시계 시간 중 먼저 만료되는 쪽을 따릅니다. 벽시계 전진은 조기 만료를 일으킬 수 있고 시계 후퇴는 단조 기한을 늘리지 못합니다. 절전 중 벽시계가 기한을 넘겨도 **다음 타이머 실행 또는 상태/실행 검사 때** 만료를 감지합니다. 백그라운드 즉시 깨우기를 보장하지 않습니다. 만료·명시 잠금·세션 종료 시 확장 상태를 먼저 지우고 `sudo -k`를 시도합니다. 실패하면 캐시가 남을 수 있으며, Pi 강제 종료 시 정리 자체를 보장하지 않습니다.

같은 TTY의 sudo timestamp는 다른 도구와 공유될 수 있으며 호스트가 전역 캐시로 설정했으면 범위가 더 넓습니다. `/sudo lock`이 다른 도구의 접근까지 무효화할 수 있고, 같은 컨텍스트의 다른 프로세스가 다시 캐시를 채울 수 있습니다. 이 확장은 같은 UID에 대한 보안 격리나 OS sudo 권한의 독점 제어가 아닙니다.

## 실패·프로세스 종료의 한계

호스트 검사 실패나 캐시 정리 실패에도 논리적 허가는 먼저 철회합니다. 정리 실패 시 원래 명령 결과 또는 인증 오류를 유지하고 별도 경고를 붙입니다. 잠금의 마지막 `-k`는 진행 중이던 인증·실행의 timestamp 갱신 경합 때문에 유지합니다.

실패 진단은 초기 `-k`, 인증 `-v`/`-A -v`, 비대화형 시험의 종료·취소·시간 초과를 나눠 보고합니다. 시험에서 수집한 stderr는 제어문자 제거 및 길이 제한 후 알림에 포함할 수 있지만 인증 입출력은 캡처하지 않습니다. 인증·시험 실패와 실행 취소·시간 초과·종료 코드 없음·프로세스/전송 오류는 접근을 철회하고 `sudo -k`를 시도합니다. 완료된 실행의 0이 아닌 종료 코드는 Pi 도구 오류이지만 기존 허가는 유지하고 기한도 연장하지 않습니다. sudo 거부와 명령 자체의 실패는 종료 코드만으로 구분할 수 없어 stderr 해석이나 재인증·추가 시험을 하지 않습니다. 인증 제한은 120초, 실행 제한은 60초(남은 기한이 더 짧으면 그 값), `-k`와 시험 제한은 각각 5초입니다. 실행 취소·잠금 시 직접 자식에 `SIGTERM`, 1초 뒤 `SIGKILL`을 시도하고 최대 약 1.5초의 종료 확인 감시를 둡니다. 직접 자식이 종료해도 후손이 출력 파이프를 붙들 수 있으므로 파이프 닫힘과 직접 자식 종료는 구분합니다. 후손 프로세스, 특히 분리된 privileged 후손 종료는 보장하지 않습니다.

직접 자식의 종료를 확인하지 못하면 해당 Pi 런타임에서 새 잠금 해제를 차단합니다. privileged 프로세스를 점검한 뒤 Pi를 재시작해야 합니다. `sudo -k` 자체의 실패나 외부 프로세스의 캐시 갱신도 무효화를 보장할 수 없는 이유입니다. Linux/macOS는 대상 환경이지만 실제 classic sudo·시스템 sudo-rs 공급자·Arch 별도 sudo-rs 인증·GUI 도우미는 자동 테스트에서 수행하지 않았습니다.
