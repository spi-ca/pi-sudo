# 보안 경계와 실패 처리

## 권한 범위

잠금 해제는 개별 명령 승인이 아니라 **모델에 열리는 넓은 권한**입니다. sudo 정책이 허용하는 절대 실행 파일과 인수를 모델이 선택할 수 있으며, 신뢰하지 않는 프로젝트 텍스트도 모델 선택에 영향을 줄 수 있습니다. `sudo_exec`는 쉘을 사용하지 않지만 실행 파일 또는 그 자식이 쉘을 띄우는 것은 막지 않습니다. 짧은 시간을 선택하고 요청을 검토하며, 사용을 마치면 `/sudo lock`을 실행하세요.

`SUDO_ASKPASS` 환경 변수가 있으면 별도 옵션 없이 OS askpass를 선택하며, 없으면 터미널 인증을 사용합니다. 설정된 값이 유효하지 않거나 인증이 실패하면 터미널 방식으로 조용히 대체하지 않습니다. askpass 모드는 기존 환경 변수 `SUDO_ASKPASS`의 절대 경로만 사용합니다. 실경로의 도우미는 root 소유의 실행 가능한 일반 파일이고 그룹/전체 쓰기가 금지되어야 하며, 실경로의 모든 상위 디렉터리도 root 소유·그룹/전체 쓰기 금지여야 합니다. 심볼릭 링크는 정규화된 대상을 검증합니다. 사용자 쓰기 가능한 Homebrew/홈 디렉터리 스크립트는 제외됩니다. 확인 대화상자에 모드와 도우미 경로가 표시되고 인증 직전에 재검증하며 선택한 실경로가 바뀌면 거부합니다. 검사와 sudo의 실제 도우미 실행 사이의 파일 교체 경합까지 막지는 못합니다. sudo 인증 자식에게만 도우미 환경 변수를 전달하고 표준 입출력은 무시합니다. GUI 환경이 없으면 인증이 실패할 수 있습니다. 이 정책은 같은 UID 프로세스를 sandbox하지 않으며 악의적인 root 또는 root 소유 도우미의 안전성을 보장하지 않습니다.

터미널 모드에서 비밀번호는 이 확장의 Pi 입력 위젯, 모델 도구 인수, 캡처 파이프나 출력에 저장·전달하지 않고 `sudo -v`의 상속된 실제 터미널에서 처리합니다. 터미널 기록, sudo/PAM 정책은 별도 영역입니다. **도구 명령의 stdout·stderr에는 비밀 정보가 포함될 수 있으며 Pi의 도구 결과로 전달됩니다.** 화면용 출력은 제한된 도착 순서의 끝부분만 보관하고 펼쳐도 버린 내용을 복원할 수 없습니다. 성공 모델 텍스트는 두 스트림의 접두부, 실행 실패 오류 텍스트는 제한된 출력 끝부분을 포함할 수 있습니다. 민감한 명령을 실행하지 마세요.

## 확장 접근과 OS 캐시는 별개

잠금 해제는 순서대로 별도 `sudo -k`(기존 timestamp 무효화), 대화형 `sudo -v`, 비대화형 `sudo -n -- /usr/bin/true` 시험을 실행합니다. `-k`와 `-v`를 하나로 합치지 않습니다. 시험 명령이 sudo 정책에서 허용되지 않으면 잠금 해제는 실패합니다. 실제 명령은 `sudo -n`을 사용하므로 정책이 거부하거나 sudo timestamp가 먼저 만료되면 프롬프트 없이 실패합니다. 성공한 실제 sudo 실행이 OS timestamp를 갱신할 수 있지만 확장 기한은 갱신하지 않습니다.

기한은 단조 시간과 벽시계 시간 중 먼저 만료되는 쪽을 따릅니다. 벽시계 전진은 조기 만료를 일으킬 수 있고 시계 후퇴는 단조 기한을 늘리지 못합니다. 절전 중 벽시계가 기한을 넘겨도 **다음 타이머 실행 또는 상태/실행 검사 때** 만료를 감지합니다. 백그라운드 즉시 깨우기를 보장하지 않습니다. 만료·명시 잠금·세션 종료 시 확장 상태를 먼저 지우고 `sudo -k`를 시도합니다. 실패하면 캐시가 남을 수 있으며, Pi 강제 종료 시 정리 자체를 보장하지 않습니다.

같은 TTY의 sudo timestamp는 다른 도구와 공유될 수 있으며 호스트가 전역 캐시로 설정했으면 범위가 더 넓습니다. `/sudo lock`이 다른 도구의 접근까지 무효화할 수 있고, 같은 컨텍스트의 다른 프로세스가 다시 캐시를 채울 수 있습니다. 이 확장은 같은 UID에 대한 보안 격리나 OS sudo 권한의 독점 제어가 아닙니다.

## 실패·프로세스 종료의 한계

호스트 검사 실패나 캐시 정리 실패에도 논리적 허가는 먼저 철회합니다. 정리 실패 시 원래 명령 결과 또는 인증 오류를 유지하고 별도 경고를 붙입니다. 잠금의 마지막 `-k`는 진행 중이던 인증·실행의 timestamp 갱신 경합 때문에 유지합니다.

인증·시험·실행 중 오류, 0이 아닌 종료, 취소, 시간 초과는 접근을 철회하고 `sudo -k`를 시도합니다. 인증 제한은 120초, 실행 제한은 60초(남은 기한이 더 짧으면 그 값), `-k`와 시험 제한은 각각 5초입니다. 실행 취소·잠금 시 직접 자식에 `SIGTERM`, 1초 뒤 `SIGKILL`을 시도하고 최대 약 1.5초의 종료 확인 감시를 둡니다. 직접 자식이 종료해도 후손이 출력 파이프를 붙들 수 있으므로 파이프 닫힘과 직접 자식 종료는 구분합니다. 후손 프로세스, 특히 분리된 privileged 후손 종료는 보장하지 않습니다.

직접 자식의 종료를 확인하지 못하면 해당 Pi 런타임에서 새 잠금 해제를 차단합니다. privileged 프로세스를 점검한 뒤 Pi를 재시작해야 합니다. `sudo -k` 자체의 실패나 외부 프로세스의 캐시 갱신도 무효화를 보장할 수 없는 이유입니다. Linux/macOS는 대상 환경이지만 실제 sudo 인증·GUI 도우미는 자동 테스트에서 수행하지 않았습니다.
