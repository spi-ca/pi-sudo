# 사용 방법

## 사전 조건

`index.ts`는 `linux` 또는 `darwin`, 비-root Pi 프로세스, root 소유이면서 실행 가능하고 그룹/전체 쓰기가 금지된 `/usr/bin/sudo`를 확인합니다. 잠금 해제에는 `ctx.mode === "tui"`와 stdin/stdout/stderr 모두 실제 TTY가 필요합니다. 그 밖의 환경에서 `/sudo unlock`은 인증을 시작하지 않습니다. `status`는 현재 확장 상태를 조회합니다. Pi 상태 표시줄은 정상 잠김 상태에서 숨겨지며, 확인·인증 대기 `⏳ sudo`, 실제 허가 중 `⚡ sudo M:SS`만 표시합니다. 남은 30초에는 굵게 강조하며, 권한은 자동 연장되지 않습니다. OS sudo 캐시 무효화에 실패하면 `⚠️ sudo`가 표시되고 자세한 오류는 알림으로 확인할 수 있습니다. 정상적인 무효화 또는 인증 흐름 이후 경고가 해제됩니다.

## 사용자 명령

| 명령 | 동작 |
| --- | --- |
| `/sudo unlock` | 에이전트 idle을 기다린 뒤 사용자 확인, 선택된 방식으로 sudo 인증 및 실행 경로 검증; 기본 5분 |
| `/sudo unlock 1` … `/sudo unlock 15` | 정수 분 단위의 고정된 유효 기간; 이미 열려 있으면 먼저 잠가야 함 |
| `SUDO_ASKPASS=/신뢰할/시스템/도우미` 환경에서 `/sudo unlock [1…15]` | TUI/TTY에서 검증된 OS askpass를 자동 선택; 변수가 없으면 터미널 인증 |
| `/sudo status` | 잠금 여부 또는 남은 시간(올림한 초) 표시 |
| `/sudo lock` | 확장 접근을 먼저 철회하고 진행 중인 직접 자식 종료 시도 후 `sudo -k` 실행 |

호환용 `/sudo unlock --askpass`와 `/sudo unlock 1 --askpass`는 `SUDO_ASKPASS`가 없으면 터미널 인증으로 대체하지 않고 확인 전에 거부합니다. 변수가 설정되어 있으면 일반 `unlock`과 동일하게 검증된 askpass를 사용합니다.

확인 거부 시 sudo를 호출하지 않습니다. 확인 화면에 선택된 인증 방식(askpass인 경우 검증된 도우미 경로)을 표시합니다. `SUDO_ASKPASS`가 없는 터미널 `unlock`은 Pi TUI를 중지하고 `sudo -v`에 터미널 입출력을 직접 물려준 다음 `finally`에서 TUI를 재개합니다. 인증 성공만으로 끝나지 않고 별도 `sudo -n -- /usr/bin/true` 실행 시험까지 통과해야 권한을 엽니다. askpass 모드는 TUI를 중지하지 않고 `sudo -A -v`의 입출력을 캡처하지 않습니다. sudo가 검증된 `SUDO_ASKPASS` 도우미를 호출하며 Pi는 비밀번호를 받거나 도우미를 직접 실행하지 않습니다. 환경 변수가 없으면 터미널 인증을 사용합니다. 변수가 설정되어 있는데 도우미 검증에 실패하거나 인증이 실패하면 터미널 모드로 대체하지 않습니다. 인증·시험 단계가 실패하면 잠긴 상태로 남습니다.

## 모델 도구

`sudo_exec`의 입력 예:

```json
{"executable":"/usr/bin/id","args":["-u"],"cwd":"/tmp"}
```

`executable`은 끝이 `/`가 아닌 NUL 없는 절대 파일 경로, `args`는 NUL 없는 문자열 배열, 선택적 `cwd`는 NUL 없는 절대 경로여야 합니다. `cwd` 생략 시 도구 컨텍스트의 `ctx.cwd`를 사용합니다. 허용 명령 목록이나 인수의 의미 검사는 없습니다. 실행은 `sudo -n -- <executable> <args...>` 형태의 직접 `spawn`이며 쉘을 거치거나 비밀번호를 다시 묻지 않습니다. 모델이 정한 프로그램 자체가 다른 명령을 실행할 수 있습니다.

성공 결과는 `exit`, `cancelled`, `timedOut`, `truncated`를 포함한 텍스트와 같은 상태의 `details`를 돌려줍니다. 모델에 전달하는 성공 텍스트는 기존처럼 stdout 접두부 다음 stderr 접두부를 연결합니다. 화면 표시에는 별도로 부모 프로세스가 관찰한 청크 도착 순서의 제한된 출력 끝부분을 사용합니다(자식 내부의 정확한 출력 순서는 보장하지 않음). 오류 결과는 Pi가 구조화된 `details`를 보존하지 않으므로, 출력이 있는 경우 같은 상태 헤더·정리 경고와 함께 도착 순서의 제한된 끝부분을 오류 텍스트에 담습니다. 따라서 오류의 이전 출력 접두부는 모델에 보이지 않을 수 있습니다. 실행 중 출력 갱신 후 프로세스 실행 자체가 예외로 끝난 경우에는 마지막으로 전송한 화면용 끝부분을 오류 설명 뒤에 붙입니다. 0이 아닌 종료 코드, 취소 또는 시간 초과는 도구 오류이며 접근을 철회합니다. 호출이 진행 중이거나 잠금·인증 중일 때 다른 호출은 거부됩니다. 입력 검증 실패나 busy 거부처럼 실행 전에 차단된 요청은 기존 허가를 자동으로 철회하지 않습니다. 원시 출력 접두부는 stdout·stderr 각각 32 KiB까지 보관하고 화면용 도착 순서 출력 끝부분은 별도 32 KiB/최대 1900줄로 제한합니다. 최종 모델 텍스트(헤더·경고 포함)는 UTF-8 48 KiB/2000줄 이내로 잘립니다. `truncated`는 모델 텍스트 및 원시 접두부의 제한을 반영하고, 화면용 보관 한도 초과도 카드에서 별도로 알립니다. 이 권한은 일반 `bash` 호출을 승격시키지 않으며, OS 캐시 만료·무효화와 확장 접근 만료·잠금은 별개입니다. 자세한 취소·캐시 한계는 [보안 경계](security.md)를 참고하세요.

## 명령 표시 카드

`sudo_exec` 호출 카드는 도구 이름 대신 `#`과 실행 파일·인수(`argv`)를 간결하게 표시합니다. 실제 도구 이름은 `sudo_exec` 그대로입니다. 실행 중 호출 제목의 저빈도 회전 표시와 경과 시간이 갱신되고 완료·오류·취소·세션 종료 시 중지됩니다. 카드 배경은 Pi의 진행·성공·오류 테마 색을 따릅니다. 기본 작업 디렉터리(명시적으로 같은 경로를 전달한 경우 포함)는 펼친 화면에만 표시하고, 다른 경로로 지정한 `cwd`는 접힌 화면에서도 표시합니다.
공백·빈 인수·따옴표는 JSON 방식으로 인용하고 제어문자는 이스케이프합니다.
이는 **표시 전용이며 복사해서 실행할 셸 명령이 아닙니다**. 실제 실행은 원본 인수 배열을 그대로 사용합니다.
접힌 호출 제목의 긴 인수·디렉터리는 기존처럼 앞부분을 화면 행 수에 맞춰 줄입니다. 접힌 실행 출력은 진행 중·완료 후 모두 화면 너비에 따라 **마지막 8개 화면 행**을 표시하고, 숨겨진 원본 줄 수와 현재 펼치기 단축키를 출력 미리보기 위에 안내합니다. 펼치면 보관된 범위만 관찰된 도착 순서로 볼 수 있습니다.
허가된 명령 실행 중에는 stdout·stderr의 제한된 스냅샷을 약 150ms 간격으로 출력이 바뀔 때만 갱신합니다. 접힌 화면에는 `Running…`과 마지막 8개 화면 행이 보이며 한도 초과 시 잘림을 알립니다. 원시 접두부가 가득 찬 뒤에도 화면용 끝부분은 계속 갱신됩니다. 인증·잠금 해제·시험·캐시 정리 출력은 스트리밍하지 않습니다. 진행 중 표시와 완료·비정상 종료·오류·취소·시간 초과 결과를 구분합니다. 구조화된 상태 정보가 있는 성공 결과의 상태 헤더는 중복 표시하지 않습니다. 구조화된 정보가 없는 오류의 원문 헤더는 진단을 위해 보존하며 모델에 전달되는 내용은 그대로입니다. 수집 단계에서 잘린 출력은 펼쳐도 복구되지 않으며, 카드에 별도로 표시합니다. `sudo -k` 정리 실패 경고도 접힌 화면에 남습니다.

카드는 별도의 실행 승인창이 아닙니다. askpass 환경이나 암호를 표시하지 않지만,
명령 인수와 명령 출력 자체는 UI 및 대화 기록에 남으므로 비밀값을 인수에 넣지 마세요.
